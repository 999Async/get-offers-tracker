# Phase 3：岗位发现与审批闭环

日期：2026-09-06。状态：**确定性基线已实现，尚不代表完整 Phase 3 质量验收通过**。

## 用户能做什么

在侧栏“岗位雷达”中选择“简历匹配”，选择个人知识库中已处理的当前简历版本，输入岗位方向和城市。结果提供岗位要求、相关简历原文、单独标明的用户确认事实，以及未找到文字依据的要求。选择岗位后，页面展示公司、岗位、简历文件版本和“待投递”状态；只有点击“确认加入”才保存记录。

确认后可直接进入现有投递列表。没有新增独立页面，也没有自动向公司投递或填写表单。原岗位目录继续保留。

## 实现与边界

- `career/discovery.py` 使用现有 AgentRuntime：读取指定简历、搜索岗位、检索并校验引用、读取投递事实、提议写入、审批、提交。最多 7 步；恢复、拒绝、过期、取消沿用事件回放机制。
- 当前控制器是 `career-discovery-lexical-v1`，**没有调用 LLM**。岗位排序沿用 Job Search；简历用于逐项核对依据，不参与一个未经验证的“匹配分”。当前证据关联是词法重合，不能推导“具备技能”“满足年限”等结论，也不生成未经证实的可迁移经历。Token 与模型费用均为 0，标记为无模型调用，而不是假模型的合成费用。
- 只允许选择已处理的当前简历版本，因为知识检索只检索当前有效版本。历史投递记录继续关联原文件版本，不随新版本上传而变化。
- 已确认事实与未经确认的原文分别处理。用户修正的陈述单独展示，不把原始陈述一起标为正确。没有文字依据只表示需要核对，不等于用户没有这项能力。
- 每个控制步骤保留 Context Manifest、工具身份、检索配置与语料/证据版本的校验值。工具返回内容始终是非可信数据；不因进入上下文而变成用户确认事实。
- Run Trace 不复制简历正文和事实正文，只保留引用 ID 与修订校验值。显示结果时按账号重新取引用并校验当前版本；知识库删除或事实修订后旧结果不可用。审批/应用记录保留文件名与版本引用作为历史元数据。
- 浏览器不能传入账号/租户，也不能任意指定待写岗位。提议岗位必须来自该账号已完成的查找结果，提交前再次验证当前岗位、简历版本和事实修订。
- 产品端 `/api/agent-plans` 由独立服务密钥保护。D1 事务同时保存写入回执与待投递记录；按账号和幂等键读取回执，参数变化拒绝，回执丢失时只做只读核对。重试不会重建用户已删除的记录；相同岗位 ID 或原岗位 URL 的现有记录不重复创建。

## 验证

- 全量服务回归：152 passed、3 skipped；跳过已有的可选真实模型/文档集成项。网页构建与 23 项 Node 测试通过；Python Ruff 和新增页面/API ESLint 通过。
- 10 个合成工作流用例：正常闭环、精确审批、重复确认、回放、引用/原文隐私、拒绝和伪造审批、删除/修正/换版、跨账号和任意岗位注入、回执丢失、审批过期、缺失简历/权限、执行中取消。
- [工作流评测报告](phase3-career-contracts.json)导出 20 条 Run Trace，记录代码与用例哈希、配置、耗时、Token/成本。完整 Trace 位于本地忽略目录 `.agent-data/phase3-eval-release/traces`。评测入口 `npm run career:eval -- --out <新的输出目录>`。输出目录不可复用，避免覆盖旧评测证据。
- 产品测试实际执行全部 SQLite 迁移，验证产品身份边界、D1 事务、文件归属、重复写入、异参数拒绝、旧岗位 ID 去重和删除后的重试。
- 浏览器验收使用用户明确授权的仅本机合成账号网关：通过真实产品 API 上传/处理合成 Markdown 简历，在页面确认经历、查找北京 Python 岗位、核对 CUDA 缺少依据、切换设置页后恢复待确认记录、点击确认并进入投递列表。真实产品 API 回读确认仅 1 条待投递，文档与版本 ID 完全一致。上传文件选择器本身未在本次验收中重复测试。
- 本次不把合成数据的通过率当成真实岗位推荐质量。经人工复核的真实职业工作流数量仍为 0。

验收后通过产品 API 删除合成投递与简历，回读确认测试账号材料和投递均为空。历史结果重新打开后不再显示被删原文。已关闭合成账号网关与隔离服务、移除临时密钥；保留正常本地预览。

## 本地配置

产品进程配置（`.dev.vars`，不要提交密钥）：

```text
AGENT_KNOWLEDGE_URL=http://127.0.0.1:8767
AGENT_KNOWLEDGE_TOKEN=<至少32字符的独立密钥>
AGENT_CAREER_URL=http://127.0.0.1:8768
AGENT_CAREER_TOKEN=<至少32字符的独立密钥>
AGENT_PRODUCT_TOKEN=<至少32字符的独立密钥>
```

Career 进程还需 `AGENT_SEARCH_URL`、`AGENT_SEARCH_TOKEN` 和 `AGENT_PRODUCT_URL`，并与产品共享上面的知识库、Career 和 Product 服务密钥。Product URL 指向产品根地址，例如 `http://localhost:5178`。所有密钥由环境注入；服务地址只接受 HTTPS 或本机 HTTP，不跟随重定向。

先启动已有 Knowledge / Search 服务，再执行 `npm run career`（默认 8768）。开发虚拟环境需已安装项目与测试依赖，不要为了启动本服务移除已有 documents/neural/r2 可选依赖。

新增迁移 `drizzle/0004_bizarre_quicksilver.sql` 创建幂等回执表。已应用于本地开发数据库；**未应用到生产、未部署**。
