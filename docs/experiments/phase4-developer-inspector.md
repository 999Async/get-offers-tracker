# Phase 4：本机运行与评测查看

2026-09-12。状态：本机开发者查看切片已实现；完整 Phase 4 与生产发布门槛保持未通过。

## 使用

从项目根目录启动：

```sh
npm run assistant:developer
```

连接本机 Codex 后打开设置 → 运行与评测 → 查看记录。该命令等价于 `npm run assistant:local -- --developer`。普通 `assistant:local` 默认不启用开发者权限；托管 Worker 不包含此开发网关。

入口读取 `.agent-data/assistant/audit/*.json` 的脱敏运行记录，以及 `.agent-data/assistant-eval/*/report.json` 与同目录下的 Trace。不会在浏览器里启动评测、调用模型、改写报告、审批或切换线上配置。尚无实验时先运行：

```sh
npm run assistant:eval -- run --mode scripted --out .agent-data/assistant-eval/first-run
```

输出目录必须是新目录。脚本模式的输入是合成用例；真实模型连通或合成契约全通过均不代表真实材料质量已验收。

## 当前可检查的内容

- 运行：按状态筛选、时间、Run ID、配置哈希，Runtime 工作流/Agent/步骤/模型/工具/审批阶段的耗时和错误类别。父阶段包含子阶段耗时，不能直接相加。旧运行状态来自 Runtime，不是生成内容的语义质量判定。
- 用量：输入/输出 token 与可用的费用；缺失值保持未知。合成运行明确标记，合成费用不作为真实费用展示。
- 实验：报告/数据集/代码/工作流/依赖哈希，执行模式，各用例契约结果、失败检查、模型/工具耗时与用量。用例以报告内顺序显示，不返回原任务、JD、回答、引用或原始 Trace。
- 比较：选择基线与候选，重新验证输入身份、用例集合、报告与 Trace 哈希，再复用既有配对逻辑，显示通过数变化、平均耗时差和变化因素。不兼容实验被拒绝。每例单次采样只提供描述统计，不作显著性判断。

## 权限与数据边界

两个开关必须同时有效：Vite 开发网关的 `GETOFFERS_LOCAL_DEVELOPER=1`，以及 Python 的 `--local-codex --developer-tools`。启动命令会设置它们。每次读取都要求回环来源、合法 Host、有效 HttpOnly 本机会话，并由 Python 再次核对会话；内部服务令牌不交给浏览器。

显式启用后，当前本机 Codex 操作者获得本机目录的 `metrics:read`、`trace:read:redacted`、`evaluation:read`。这不是托管站点的角色管理，也不是按租户分配的生产权限服务。无法通过浏览器传入账号、能力、任意路径或受限 Trace 权限。账号变更后页面立即清除已展示数据，后续读取重新认证。

API 重新按字段白名单投影，排除原任务、消息、草稿、JD、引用原文、Context Manifest 正文和文件路径。通过随机会话访问服务，文件选择使用服务端目录产生的哈希 ID；路径越界、软链接、损坏记录与超大文件被拒绝。每次最多枚举 500 份文件、读取 32 MB，单文件上限 8 MB、单实验上限 100 条用例；触及读取上限显示列表不完整。

能力检查记入本机 `.agent-data/developer/access.jsonl`，包含操作者哈希、动作、允许/拒绝与时间；不记录邮箱或正文。审计写入失败时拒绝读取。服务令牌/会话层拒绝与逐文件读取结果暂未形成完整生产审计事件。此日志没有自动保留期限和轮转；不将其描述成完整访问治理。

普通聊天仍只持久化既有脱敏审计，完整 Run Event 不因此新增落盘。此视图不是任意历史聊天的完整重放器；评测 Trace 校验也不会重复执行工具或模型。
