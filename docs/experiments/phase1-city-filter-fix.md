# 自然语言城市筛选修复

2026-09-06。修复搜索入口缺少城市意图解析的问题：此前 `query` 中的 Fontana 只参与检索打分，`hard_constraints.cities=[]` 导致其他城市仍有资格进入结果；显式传入城市时，事实筛选和 Qdrant 过滤均正常。

## 变更

- 四种检索方式在召回前共用 `city-intent-v1`：解析支持的中英文地点表达，与显式城市条件取交集，城市排除条件累积。
- 偏好表达不会升级成硬筛选；没有匹配岗位时不放宽城市，冲突条件返回无效请求。
- 城市词表仅使用当前用户可见的岗位事实，并补充常用中文城市和完整 `City, ST` 表达。规则范围与限制见 `services/agent/SEARCH.md`。
- 响应和评测逐例保存实际条件、命中的城市文字与解析器版本。约束违规计数使用实际生效条件；解析正确性仍需独立审核。
- 保留冻结标签、历史报告与审核 CSV，本次没有修改岗位城市事实或进行线上部署。

## 验证

最小复现使用相同职位的 Fontana 和 San Jose 两份岗位。修复前以下测试四种模式均失败：实际返回两城岗位，预期仅 Fontana；修复后通过，并检查传入召回的允许集合已排除 San Jose。

```sh
services/agent/.venv/bin/pytest services/agent/tests/test_job_search.py -q -k natural_language_city
```

两条原始查询 `official-17-1`、`official-17-4` 同时加入四模式回归测试，使用真实冻结 JD、Qdrant 本地索引和确定性的测试 encoder/reranker；此部分验证筛选链路，不声称重跑真实 BGE。
