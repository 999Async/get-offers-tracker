## 使用

本机已登录 Codex 时，无须为评测另配 API Key：

```sh
npm run assistant:eval -- check --provider codex
npm run assistant:eval -- run --provider codex --limit 1 --out .agent-data/assistant-eval/codex-smoke-001
```

`check` 调用官方本机账号与模型列表接口，并检查 CLI 版本；不执行推理，不检查余额或质量。默认选择当前账号的默认模型，可通过 `--model` 指定账号模型列表中的模型。账号、模型或 CLI 版本不可用时退出，不回退为脚本模型。不能将 `--provider codex` 与 `--env-file` 或 `--mode scripted` 组合；兼容 API 模式保留原有用法。

真实调用仍走既有 CodexProvider：临时工作目录、禁用原生工具、只返回结构化决策，实际工具由 GetOffers Runtime 与策略执行。单用例最多 8 步、5 分钟，单次模型进程有独立超时。报告记录 provider、模型、适配器版本、CLI 版本和供应商返回的 token 用量，不包含登录邮箱或凭据。Codex 没有配置计费单价，因此费用保持未知。

## 把审核表接入页面

1. 打开实验目录中的 `review.csv`，另存为同目录的 `reviewed.csv`。原始报告与来源列保持不变。
2. 只填写最后五列：`fact_support`、`usefulness`、`jd_fit`、`reviewer`、`notes`。标签和填写规则见[审核指南](phase4-assistant-evaluation.md#人工审核)。缺乏依据时保留 `pending`。
3. 运行 `npm run assistant:developer`，在设置 → 运行与评测 → 评测实验中刷新并打开报告。

页面只认同目录的 `reviewed.csv`，不会把导出的待审核模板自动视为审核结果。读取时重新校验报告、Trace、原始来源列和逐例指纹，再统计三种审核维度。审核姓名由操作者自行填写，尚无独立身份认证；浏览器只接收枚举标签、计数、比率和审核指纹，不接收姓名、备注、原始回答与材料。

缺少审核表显示未提供；无效表显示原因类别和修复提示，报告仍可查看，评分不进入统计。文件上限、请求读取预算、软链接拒绝及权限边界沿用[本机查看器](phase4-developer-inspector.md)。畸形 CSV、缺列、多列或过大的字段均按无效审核处理。

通过率的分母是 `pass + fail`，`pending` 与 `n/a` 单独列出。没有已评分用例时显示“未评分”；真正的零通过率显示 `0%`。逐例评分可展开查看。

配对比较要求两组原始实验兼容。人工差值还要求两份审核表有效，并按同一用例、同一维度纳入两侧均为 `pass/fail` 的评分。页面同时显示有效配对数、排除数量和候选减基线的百分点差值；零配对显示“未比较”。任一审核表缺失或无效时仍可比较自动契约，但不计算人工差值。本次比较返回两份审核指纹，便于核对所用版本；页面不会保存或提交审核、调用模型、改写报告或触发发布。
